# 第 1 课：为什么是追加日志

对应 DDIA 第 3 章开头「驱动数据库的数据结构」。

## 1. 世界上最简单的数据库

DDIA 用两行 bash 开场：

```bash
db_set () { echo "$1,$2" >> database; }
db_get () { grep "^$1," database | sed -e "s/^$1,//" | tail -n 1; }
```

- `db_set` 只往文件末尾追加，从不修改旧数据。写入是 O(1)，而且是**顺序写**。
- `db_get` 要扫描整个文件，取最后一次出现的值。读是 O(n)。

这两行代码已经包含了整个阶段 1 要解决的问题：

| 问题 | 阶段 1 的解法 |
|---|---|
| 读要扫全文件，太慢 | 索引（我们用稀疏索引） |
| 文件无限增长 | 分段（segment）+ 删除旧段 |
| 同一个 key 的旧值浪费空间 | 日志压缩（compaction） |
| 写到一半断电，尾部是垃圾 | 校验和 + 启动时截断 |
| 值里含有逗号、换行怎么办 | 二进制记录格式 + 长度前缀 |

## 2. Kafka 的日志和数据库的日志有什么不同

Kafka 关心的是 **offset**（第几条记录），不只是 key。消费者说「从 offset 1000 开始给我」，
所以我们的核心接口是：

```go
Append(record) (offset uint64, err error)
Read(offset uint64) (record, error)
```

key 只在「日志压缩」时才登场。

## 3. 思考题（先自己想，再看下一课）

1. 为什么几乎所有存储系统（Kafka、LSM 树、数据库的 WAL）都选择「只追加」，而不是原地修改？
   至少说出两个理由。提示：磁盘的物理特性；崩溃时会发生什么。
2. 一条记录写进文件后，读的时候怎么知道它在哪里结束？列出你能想到的方案，比较优劣。
3. 写到一半断电，文件尾部会是什么样子？重启时你怎么**发现**它，发现后怎么**处理**？

## 面试官会怎么问

- 「Kafka 为什么快？」顺序 IO、页缓存、零拷贝、批量。顺序 IO 就是本课的核心。
- 「追加日志的缺点是什么？」读放大、空间放大，需要索引和压缩来弥补。

## 4. 思考题讲解（第一次作答之后）

### 题 1：为什么只追加

你的答案「写入快，像数组末尾追加」是最重要的一条。补充细节：

- **顺序 IO 远快于随机 IO。** 机械盘随机写要寻道（毫秒级），顺序写几乎没有寻道。SSD 上顺序写也更友好，
  因为 SSD 按块擦除，原地改小块数据会造成写放大。操作系统还能把连续的小写合并成大写。
- **崩溃安全。** 原地修改时，断电可能让一条旧记录变成「一半旧、一半新」，旧值也找不回来。
  只追加时，已经写好的数据永远不会被碰，坏的最多是**文件尾部**那一条。恢复只需检查尾部。
- **并发简单。** 已写入的部分不再变化，读者可以不加锁地读旧数据，只有写者需要串行。
- **日志本身就是历史。** 复制（把日志发给 follower）、重放、审计、流处理，都建立在这一点上。
  这也是 DDIA 整本书的主线。

### 题 2：怎么知道记录在哪结束

你的答案就是工业界的标准答案：**长度前缀**。要澄清一点：固定长度的是**头部**
（比如 4 字节的 length 字段），后面的内容长度是可变的，文件总长度不固定。

| 方案 | 问题 |
|---|---|
| 每条记录定长 | 浪费空间，而且值超长就放不下 |
| 分隔符（比如换行） | 值里出现分隔符就要转义，bash 版本遇到逗号、换行就坏了 |
| 长度前缀 | 头部开销几个字节，几乎没有缺点 |

### 题 3：半写记录

- **时间戳不行**：时间戳本身可能写完整了，后面的内容却只写了一半；断电还可能留下垃圾字节。
  时间戳回答的是「什么时候写的」，回答不了「内容对不对」。
- **「写完整之后才能消费这个 id」**：这个想法很好，它其实是阶段 3 的 **high watermark（已提交位置）**
  的雏形。但它解决的是「谁可以读」，解决不了「重启后怎么发现尾部坏了」。
- **标准做法：每条记录带校验和（CRC32）。** 重启时从头（或从某个检查点）逐条扫描：
  长度字段读不全、内容长度不够、CRC 对不上，任何一种情况出现，就说明从这里开始是半写数据，
  把文件**截断**到这条记录的起点。
- **串行会不会慢？** 你注意到了真问题。单个日志确实只有一个写者，Kafka 每个分区也是这样。
  但顺序写本身很快；要更高吞吐，靠的是**批量写**和**多个分区并行**（阶段 4）。
